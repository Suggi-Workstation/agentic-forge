# LEARNINGS.md -- Curated Method Memory

Reusable lessons about how the Forge behaves and how to run research.
Chronology belongs in `logbook/`; domain conclusions belong in build
packages. This file contains only methods that transfer across pipelines.

## Admission and Size Rules

- The Analyst may add a lesson only after the same method pattern is
  supported by at least two completed pipelines whose Analyst verification
  passed and whose human disposition was not rejection.
- Each lesson names its evidence pipeline IDs, confidence, first observed,
  and last tested. Generic advice without evidence is rejected.
- Keep at most twelve active lessons, each no longer than eight short lines.
- Before adding beyond the cap, move the least-current lesson intact to
  `forge/archive/learnings-<YYYY-MM-DD>.md`; never silently delete it.
- A protocol or skill change still requires human approval. A learning is
  evidence, not self-authorization.
